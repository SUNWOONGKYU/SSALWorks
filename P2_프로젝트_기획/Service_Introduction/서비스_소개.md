> **용도:** Production/index.html의 서비스 소개 페이지
> **구조:** 8개 섹션 통합 구성

## 1. 개요

<span style="color: #6B7280;">※ 모바일에서는 조회만 가능합니다. 개발 작업은 PC에서 진행하세요.</span>

**SSAL Works**는 Claude Code를 활용하고 차별화된 체계적 방법론을 적용하여 풀스택 웹사이트를 개발하는 플랫폼입니다.

- **Claude Code**: Anthropic이 만든 AI 코딩 도구로, 사람 대신 코딩을 수행합니다.
- **체계적인 방법론**: 10단계 진행 프로세스, SAL Grid, 3단계 검증, AI 규칙 체계의 4가지로 구성되어 개발 전 과정을 관리, 통제, 검증하여 품질을 확보합니다.
- **풀스택**: 프론트엔드(화면) + 백엔드(서버/API) + 데이터베이스를 모두 갖춘 완전한 웹사이트입니다.
- **SSAL**: S(Sunny) + SAL(Stage, Area, Level의 3차원 좌표계). 한글 발음 "쌀"은 핵심 먹을거리를 의미합니다. 황금쌀 방앗간처럼, 아이디어를 가져와서 돈 버는 풀스택 웹사이트를 만드는 곳입니다.

<span style="font-size: 12px;">코딩 등 개발 지식이 없어도, 아이디어, 염원, 의지만 있으면 실제 비즈니스에 사용할 수 있는 완전한 풀스택 웹사이트를 만들 수 있습니다.</span>

| **직장인 부업**: 퇴근 후 시간을 활용해서 뭔가 만들고 싶다 | 매일 조금씩 → 완성된 웹서비스 |

| **기존 사업자**: 외주 맡기면 수천만원~수억원인데... | 300만원 + 직접 컨트롤 가능 |

**바이브 코딩의 한계**

**바이브 코딩(Vibe Coding)**이란 AI에게 "이거 만들어줘"라고 말하고 결과물을 받는 방식입니다. 간단한 것은 되지만, 복잡한 프로젝트에서는 한계가 있습니다.

- "로그인 기능 추가해줘" → 파일 20개 생성 → 어디에 뭐가 있는지 모름
- "버튼 색깔 바꿔줘" → 다른 기능이 망가짐 → 되던 게 안 됨
- 대화 100턴 넘어감 → AI가 앞에서 한 걸 까먹음 → 같은 실수 반복
- 3일 작업한 결과물 → 꼬여서 수습 불가 → 결국 처음부터 다시...

**SSAL Works는 체계적인 방법론으로 이 문제를 해결합니다.**

## 2. SSAL Works란 무엇인가


### 2-1. SSAL Works의 정체성

SSAL Works는 **Claude Code를 활용한 3차원 SAL Grid 기반 풀스택 웹사이트 개발 실행 및 관리 플랫폼**입니다.

이 정의를 하나씩 풀어서 설명하겠습니다.


#### Claude Code란?

Claude Code는 Anthropic이 개발한 AI 도구입니다. 터미널에서 실행되며, 사용자의 지시를 받아 코드를 작성하고, 파일을 만들고, 프로젝트를 관리합니다.

**Claude Code의 역할:**

- **코드 작성**: HTML, CSS, JavaScript, TypeScript, Python 등
- **파일 생성 및 수정**: 프로젝트 파일 자동 생성
- **Git 버전 관리**: 커밋, 푸시, 브랜치 관리
- **터미널 명령 실행**: npm, git, 배포 명령 등
- **프로젝트 구조 관리**: 폴더 생성, 파일 정리
- **코드 리뷰**: 작성한 코드 검토
- **버그 수정**: 에러 분석 및 해결
- **테스트 실행**: 자동화 테스트 수행

**Claude Code vs 일반 Claude:**

- **Claude (웹/앱)**: 브라우저/앱에서 실행, 파일 접근 불가, 코드 실행 불가, Git/배포 작업 불가, 대화/질문/문서 작성 용도
- **Claude Code (터미널)**: 터미널(CLI)에서 실행, 로컬 파일 직접 접근 가능, 코드 직접 실행 가능, Git/배포 작업 직접 수행, 실제 개발 작업 용도

SSAL Works는 이 Claude Code를 핵심 도구로 사용하여, 비개발자도 풀스택 웹사이트를 개발할 수 있게 합니다.


#### 3차원 SAL Grid란?

SAL Grid는 SSAL Works가 개발한 프로젝트 관리 방법론입니다.

**SAL = Stage(단계) + Area(영역) + Level(레벨)**

```
Area (Y축)
   ↑
   │ ┌──┬──┬──┐
   │ │  │  │  │
   │ ├──┼──┼──┤
   │ │Task│  │ ← Level
   │ ├──┼──┼──┤
   │ │  │  │  │
   │ └──┴──┴──┘
   └─────────→ Stage (X축)
```

**Stage (X축 - 개발 단계):**

- **S1 (Development Setup, 개발 준비)**: 환경설정, DB 스키마, Auth 설정
- **S2 (Auth & Registration, 개발 1차)**: OAuth, 이메일, 회원가입
- **S3 (AI Integration, 개발 2차)**: AI 연동, AI Q&A
- **S4 (Payment & Admin, 개발 3차)**: 결제, 관리자, 크레딧
- **S5 (Development Stabilization, 개발 마무리)**: 배포, QA, 안정화

**Area (Y축 - 개발 영역):**

- **M (Documentation, 문서화)**: 기획서, 명세서 등
- **U (Design, UI/UX 디자인)**: 화면 설계, 디자인
- **F (Frontend, 프론트엔드)**: 사용자가 보는 화면
- **BI (Backend Infrastructure, 백엔드 기반)**: 서버 설정, 라이브러리
- **BA (Backend APIs, 백엔드 API)**: API 엔드포인트
- **D (Database, 데이터베이스)**: DB 스키마, 쿼리
- **S (Security, 보안/인증)**: 로그인, 권한 관리
- **T (Testing, 테스트)**: 단위/통합 테스트
- **O (DevOps, 운영/배포)**: 배포, CI/CD
- **E (External, 외부 연동)**: 외부 서비스 연동
- **C (Content System, 콘텐츠 시스템)**: 콘텐츠 관리

**Level (Z축 - 작업 순서):**

Level은 각 Task의 Stage별, Area별 순서를 나타냅니다.

예: S2F1, S2F2, S2F3 → Stage 2, Frontend Area의 1번, 2번, 3번 Task


#### Task의 22개 속성

SAL Grid에서 각 Task는 22개의 속성으로 관리됩니다.

- **#1 task_id**: Task 고유 ID (예: S2F1)
- **#2 task_name**: Task 이름
- **#3 stage**: Stage 번호 (1~5)
- **#4 area**: Area 코드 (M, U, F, BI, BA, D, S, T, O, E, C)
- **#5 level**: Level 번호
- **#6 task_status**: 작업 상태 (Pending → In Progress → Executed → Completed)
- **#7 task_progress**: 진행률 (0~100)
- **#8 dependencies**: 선행 Task
- **#9 task_instruction**: Task 수행 지침
- **#10 task_agent**: Task 수행 Agent
- **#11 generated_files**: 생성된 파일
- **#12 duration**: 소요 시간
- **#13 build_result**: 빌드 결과
- **#14 verification_instruction**: 검증 지침
- **#15 verification_agent**: 검증 Agent
- **#16 test_result**: 테스트 결과
- **#17 build_verification**: 빌드 검증
- **#18 integration_verification**: 통합 검증
- **#19 blockers**: 차단 요소
- **#20 comprehensive_verification**: 종합 검증
- **#21 ai_verification_note**: AI 검증 의견
- **#22 stage_gate_status**: Stage Gate 상태


#### 왜 SAL Grid가 필요한가?

**체계 없는 코딩은 시행착오가 많습니다.**

AI가 아무리 뛰어나도 관리 시스템 없이 방치하면:
- 여기저기에 폴더와 파일을 만듭니다
- 일관성 없이 코드를 작성합니다
- 수정 작업이 매우 어려워집니다
- 어떤 파일이 어디에 있는지 찾기 힘듭니다

**AI도 관리 시스템이 필요합니다.**

SAL Grid는 모든 개발 작업(Task)을 3차원 좌표계 위에 배치하여:
- 체계적으로 관리합니다
- 모든 작업을 추적합니다 (Audit Trail)
- 작업자와 검증자를 분리합니다
- 단계별 품질을 보장합니다


#### 풀스택 웹사이트란?

프론트엔드(사용자가 보는 화면)와 백엔드(서버, 데이터베이스, API)가 모두 갖춰진 완전한 웹사이트입니다.

**풀스택 웹사이트의 구성:**

```
┌────────────────────────┐
│   Frontend (화면)      │
│   HTML, CSS, JS        │
└──────────┬─────────────┘
           ↓↑
┌──────────┴─────────────┐
│   Backend (서버)       │
│   API, 비즈니스 로직    │
└──────────┬─────────────┘
           ↓↑
┌──────────┴─────────────┐
│   Database (DB)        │
│   데이터 저장/조회      │
└────────────────────────┘
```

단순한 랜딩 페이지가 아니라, 회원가입, 로그인, 결제, 데이터 저장, 관리자 기능 등 실제 비즈니스를 운영할 수 있는 웹사이트입니다.


### 2-2. SSAL이라는 이름의 의미

SSAL이라는 이름은 두 가지 의미가 결합되어 있습니다.

#### 첫째, S + SAL

S는 개발자 Sunny의 성씨 첫 글자이고, SAL은 3차원 좌표계(Stage, Area, Level)의 약자입니다. 따라서 SSAL = Sunny + Stage + Area + Level입니다.


#### 둘째, 쌀

SSAL의 한글 발음은 "쌀"입니다. 쌀이 한국인의 핵심 먹을거리이듯, 웹사이트는 사업의 핵심 먹을거리입니다. 쌀이 있어야 밥을 먹듯, 웹사이트가 있어야 수익을 냅니다. SSAL Works에서 만드는 웹사이트는 사용자에게 돈을 벌어다주는 핵심 먹을거리가 됩니다.


### 2-3. 황금쌀 방앗간

SSAL Works를 비유적으로 표현하면 **"황금쌀 방앗간"**입니다.

```
┌────────────────────────┐
│    황금쌀 방앗간        │
├────────────────────────┤
│ 농부 (사람)             │
│    │                   │
│    │ 벼 (아이디어)      │
│    ↓                   │
│ ┌────────────────────┐ │
│ │ 방앗간 (SSAL Works) │ │
│ │ Claude Code +       │ │
│ │ SAL Grid            │ │
│ └────────────────────┘ │
│    │                   │
│    │ 쌀 (웹사이트)      │
│    ↓                   │
│ 황금쌀 (수익 창출)       │
└────────────────────────┘
```

농부(빌더)가 벼(창의적 아이디어)를 가져오면, 방앗간(SSAL Works)에서 방아(AI)가 찧어서 쌀(풀스택 웹사이트)을 만들어냅니다. 그리고 그 쌀은 황금쌀, 즉 돈을 버는 웹사이트가 됩니다.

방앗간에서 농부가 직접 방아를 찧지 않아도 쌀이 나오듯이, SSAL Works에서 사용자가 직접 코딩을 하지 않아도 웹사이트가 만들어집니다.


### 2-4. 인간과 AI의 역할 분담

SSAL Works에서 인간과 AI는 각자의 역할이 명확하게 분담되어 있습니다.

#### AI(Claude Code)가 담당하는 것

- **코딩**: HTML, CSS, JavaScript, TypeScript 등 작성
- **문법과 문서 형식**: 올바른 문법, 표준 형식 준수
- **도구 사용**: Git, npm, Vercel CLI 등 도구 활용
- **반복적인 작업**: 파일 생성, 코드 수정 반복
- **기술적인 구현**: 알고리즘, 로직 구현
- **에러 해결**: 버그 분석 및 수정
- **테스트**: 자동화 테스트 수행

#### 인간(빌더)이 담당하는 것

- **기획**: 무엇을 만들 것인지 결정
- **의사결정**: 어떤 방향으로 갈 것인지 결정
- **비즈니스 모델**: 어떻게 수익을 낼 것인지 설계
- **Order Sheet 작성**: AI에게 지시할 내용 정리
- **최종 승인**: 결과물 검토 및 승인
- **외부 서비스 설정**: API 키 발급, OAuth 설정 등


## 3. 왜 SSAL Works를 만들었는가


### 3-1. Sunny의 10년간 3번의 시도 (2013-2022)

SSAL Works의 개발자 Sunny는 2013년부터 2022년까지 10년간 3개의 IT 플랫폼 개발을 시도했습니다.

- **첫 번째 시도 (2013)**: 기업 지원 서비스 거래 플랫폼 → 미완
- **두 번째 시도 (2018)**: 온라인 액셀러레이터 플랫폼 → 미완
- **세 번째 시도 (2022)**: 스타트업 지식 제공 플랫폼 → 미완


**세 가지 모두 미완으로 끝난 이유**

원인은 매번 같았습니다:

- **개발자 구인 어려움**: 실력 있는 개발자를 찾기가 너무 어려움
- **높은 개발 비용**: 외주 개발 비용이 수천만원~수억원
- **의사소통 한계**: 원하는 것을 개발자에게 정확히 전달하기 어려움
- **결과물 불일치**: 만들어진 결과물이 원하던 것과 다름

매번 같은 생각이 들었습니다:

> **"내가 직접 개발할 수 있다면..."**


### 3-2. Sunny의 배경

공인회계사로 회계감사 업무를 담당했고, 10년 이상 스타트업 액셀러레이터로 활동했습니다.

- **회계감사 경험**: 체계적인 검증 프로세스 → SAL Grid 방법론의 기반
- **액셀러레이터 경험**: 스타트업들의 개발 진입장벽 문제를 직접 목격


### 3-3. AI와의 만남 (2025년 5월)

2025년 5월, Sunny는 AI를 발견했습니다.

직접 해보니까 놀라운 사실을 깨달았습니다:

- 개발팀 없이 혼자서 개발할 수 있다
- 외주 비용이 필요 없다
- 원하는 것을 직접 만들 수 있다
- AI에게 직접 설명하면 된다

10년간 갈망했던 것의 해결 실마리를 발견한 순간이었습니다.


### 3-4. 7개월간의 몰입 (2025년 5월 ~ 12월)

2025년 5월부터 12월까지 7개월간, Sunny는 하루 평균 12시간 이상을 AI와 함께 개발에 투입했습니다.

7개월간(2025년 5월~12월) 2,500시간 이상을 투입했고, 토큰 비용만 수천만원이 들었습니다. 공인회계사 합격 이후 처음 느끼는 몰입도였습니다.

웹개발 기초부터 고급 기술까지 공부하고, Claude, ChatGPT, Gemini, Perplexity 등 다양한 AI를 사용했습니다. 수많은 에러와 버그를 해결하고, 무수한 삽질과 재시도를 거쳐 실전에서 검증된 노하우를 축적했습니다.


### 3-5. 3개월 만에 만든 웹사이트

7개월간 이 모든 일을 하면서, 실제 웹사이트 개발은 10월부터 시작해서 12월에 완료했습니다. 3개월 미만 만에 풀스택 웹사이트(SSAL Works)를 완성한 것입니다.

**10년 vs 3개월**

과거 10년간은 3번 시도해서 모두 미완이었습니다. 개발팀이 필요했지만 구하지 못했고, 비용만 들고 결과가 없었습니다. 기획만 가능했습니다.

이제 3개월 만에 1번 시도로 완성했습니다. 개발팀 없이 토큰 비용만으로, 전체 개발을 직접 할 수 있게 되었습니다.

Sunny는 이제 풀스택 웹사이트를 일주일에 하나씩 만들 수 있는 능력이 생겼습니다.


### 3-6. SSAL Works를 만든 이유

이 능력을 다른 사람들에게 공유하고 싶습니다.

> **"많은 사람들이 SSAL Works를 통해 같은 능력을 갖게 되기를 바랍니다."**

개발 능력이 없어도 웹사이트를 만들 수 있게 진입장벽을 제거하고, 2,500시간의 노하우로 삽질을 줄여주고, 웹사이트로 돈을 벌 수 있게 도와주고 싶습니다.


### 3-7. AI에 대한 현실적 인식

개발 기술을 몰라도 웹사이트를 만들 수 있는 방법론. 그 방법론을 만들어서 제공하려는 것이 SSAL Works입니다.

웹사이트를 만들고 싶은 의지가 있다면, 공부부터 하지 말고 바로 시작하세요. 개발하는 과정에서 필요한 지식은 SSAL Works에 다 정리해놓았습니다.


## 4. SSAL Works가 제공하는 것


### 4-1. 핵심 방법론 및 체계

SSAL Works는 4가지 핵심 방법론과 체계를 기반으로 합니다.


**4-1-1. SAL Grid**

3차원 좌표계(Stage, Area, Level)로 프로젝트 전체를 관리하는 방법론입니다.

**핵심 특징:**
- 각 Task를 22개 속성으로 체계적으로 관리
- Task Agent(작업자)와 Verification Agent(검증자) 분리
- 모든 작업의 Audit Trail 보장으로 추적 가능
- 단계별 Stage Gate 승인 절차
- 철저한 문서화 및 기록

**Task 상태 전이:**

```
Pending
   ↓
In Progress
   ↓
Executed (작업 완료)
   ↓
Completed (검증 후)
```

**검증 상태 전이:**

```
Not Verified
   ↓
In Review
   ↓
Verified
(또는 Needs Fix)
```


**4-1-2. Briefing(안내문)**

각 개발 단계마다 무엇을 해야 하는지 상세히 안내하는 문서입니다.

**"뭘 해야 할지 몰라서 멍하니 있는 시간"**을 없앱니다. 회원가입 후 환영 메시지, 프로젝트 등록 후 플랫폼 사용법, P0~P3 기획 단계별 안내, S0~S5 개발 단계별 안내, 완료된 프로젝트 수정 등 상황별 안내문이 준비되어 있습니다.


**4-1-3. Order Sheet**

AI에게 체계적으로 작업을 지시하는 표준화된 양식입니다.

AI에게 "이거 해줘"라고만 하면 엉터리가 됩니다. Order Sheet는 AI가 지켜야 할 규칙을 명확하게 정의하고, 작업 내용을 구체적으로 기술하며, 기대 결과물을 명시합니다.

**Order Sheet 구성:**
- **Part A**: 모든 프로젝트에 공통으로 적용되는 표준 규칙 (7대 작업 규칙, 5대 절대 규칙, 상태 전이 규칙 등)
- **Part B**: 프로젝트별로 커스터마이징하는 부분 (프로젝트 정보, 작업 지시, 참고 파일, 기대 결과물)


**4-1-4. 데이터 로컬 저장**

모든 프로젝트 자료가 서비스 회사 서버가 아닌 빌더의 컴퓨터에 저장됩니다.

| 걱정 | SSAL Works 답변 |
|------|----------------|
| "서비스 망하면 어떡해요?" | 파일은 내 컴퓨터에 있어서 괜찮습니다 |
| "구독 끊으면 못 보나요?" | 아니요, 파일은 계속 내 것입니다 |
| "데이터 유출 걱정돼요" | 서비스 회사 서버에 안 올라가니까 안전합니다 |
| "나중에 옮기기 어렵나요?" | 폴더 복사만 하면 됩니다 |

**유일하게 수집하는 정보:** 진행률만 수집합니다. 파일 내용, 코드 내용, 기획 문서 내용은 절대 수집하지 않습니다.

### 4-2. 이용 가능 기능

**모든 회원**

무료로 회원 가입 후 이용할 수 있는 기능입니다.

1. **Briefing(안내문) 34개 열람**: 회원가입 후 환영 메시지부터 P0~P3 기획 단계, S0~S5 개발 단계, 완료 후 수정까지 상황별 안내문

2. **Order Sheet 템플릿 32개 열람**: P0~P3 기획 단계 19개, S0~S5 개발 단계 12개, 완료된 프로젝트 수정용 1개

3. **SAL Grid Viewer 예시 확인**: 66개 Task가 어떻게 체계적으로 관리되는지 예시 프로젝트로 확인

4. **Books 80편 열람**: Claude/Claude Code 사용법(34편), 풀스택 웹사이트 개발 기초지식(34편), 프로젝트 관리 방법(12편)

5. **Tips 65개 열람**: 7개월간 AI와 함께 개발하면서 발견한 18개 카테고리의 실전 노하우

6. **외부 연동 설정 Guide 5개 열람**: Supabase, Google OAuth, Resend, Vercel, TossPayments 설정 가이드

이 외에도 공지사항 열람, My Page 프로필 관리, 인앱 알림 수신 등 기본 기능을 이용할 수 있습니다.


**빌더 계정 개설자**

빌더 계정을 개설하면 위 기능에 더해 아래 9가지 기능을 추가로 사용할 수 있습니다.


**4-2-1. 프로젝트 등록 및 Dev Package 다운로드**

프로젝트명과 설명을 입력하면 등록번호가 부여되고, Claude Code 실행 즉시 모든 규칙이 자동 적용되는 Dev Package를 다운로드할 수 있습니다.

**Dev Package란?**

Claude Code(AI)와 함께 웹 프로젝트를 처음부터 끝까지 수행할 수 있도록 설계된 **통합 개발 환경 패키지**입니다. **"다운로드 → 압축 해제 → Claude Code 실행"** 3단계로 프로젝트 개발 환경이 완성됩니다.

**Dev Package 구성 요소:**
- 프로젝트 디렉토리 구조 (P0~S5 총 10단계)
- AI 협업 설정 (7대 작업 규칙, 5대 절대 규칙 미리 설정)
- 자동화 시스템 (코드 저장부터 배포까지 자동화)
- SAL Grid 시스템 (Task별 수행 지침과 검증 기준)
- 배포 구조 (Vercel 배포 준비 완료)

**예상 절약 시간: 4~6주**


**4-2-2. Order Sheet로 Claude Code에게 작업 지시**

각 단계별로 제시된 Briefing(안내문)과 Order Sheet 템플릿을 활용하여 Claude Code에게 체계적으로 작업을 지시합니다.

```
┌─────────────────────────────────────────┐
│  Order Sheet 사용 프로세스               │
├─────────────────────────────────────────┤
│ 1. 템플릿 선택 및 Part B 작성            │
│        ↓                                │
│ 2. Human_ClaudeCode_Bridge/Orders/      │
│    폴더에 저장                           │
│        ↓                                │
│ 3. AI에게 읽고 작업하도록 지시           │
│        ↓                                │
│ 4. 결과 확인 및 검증                     │
└─────────────────────────────────────────┘
```


**4-2-3. 작업 Reports 불러오기**

Claude Code가 수행한 작업 결과를 Reports에서 확인할 수 있습니다.

**Reports에 기록되는 것:**
- 수행한 작업 내역
- 생성된 파일 목록
- 검증 결과
- 발생한 이슈 및 해결 방법


**4-2-4. 10단계 진행 프로세스 진척도 확인**

P0~P3(기획 4단계) + S0~S5(개발 6단계)의 10단계로 프로젝트 진도를 관리합니다. 각 단계별 진척률이 자동으로 계산되어 대시보드에 표시됩니다.


**4-2-5. SAL Grid Viewer로 개발 진행 현황 확인**

66개 Task를 22개 속성으로 관리합니다.

**SAL Grid에서 관리하는 것:**
- Task별 작업 상태 (Pending → In Progress → Executed → Completed)
- 검증 상태 (Not Verified → In Review → Verified)
- 작업 지시서 및 검증 지시서
- 생성된 파일 목록
- 차단 요소 및 해결 현황


**4-2-6. 예시 프로젝트 전체 소스코드 복사**

SSAL Works 전체 소스코드(Frontend, Backend, Database, 설정 파일)를 Google Drive에서 열람하고 다운로드할 수 있습니다.

```
예시 프로젝트 활용 프로세스

1. 소스코드 다운로드
       ↓
2. 구조 및 코드 분석
       ↓
3. 수정 지시 작성
       ↓
4. Claude Code에게 전달
       ↓
5. 결과물 확인
```


**4-2-7. AI Tutor 사용**

SSAL Works에 구비된 지식(Books 80편, Tips 65개, Guide 5개)을 기반으로 AI가 맞춤형 답변을 제공합니다.

**질문 예시:**
- "Claude Code 설치 방법 알려줘"
- "SAL Grid가 뭐야?"
- "Order Sheet 어떻게 작성해?"

학습 콘텐츠를 직접 찾아보지 않아도, AI Tutor에게 질문하면 관련 내용을 정리해서 답변합니다.


**4-2-8. 다른 AI에게 질문하기**

ChatGPT(코드 작성, 문서 생성), Gemini(코드 리뷰, 설계 질문), Perplexity(검색 기반 최신 정보) 등 다양한 AI에게 질문할 수 있습니다. 각 AI 서비스를 별도 구독할 필요 없이 크레딧 방식으로 이용합니다.


**4-2-9. Sunny 1:1 코칭 (3개월)**

처음 3개월간 Sunny가 1:1로 맞춤형 코칭을 제공합니다.

**개발 코칭**: Claude Code 사용법, 표준 디렉토리 구조, Order Sheet 작성법, SAL Grid 관리법, AI 에러 대응법, 프론트엔드/백엔드/DB/외부연동/배포 전 과정 지원

**창업 멘토링**: 사업 아이디어 검증, 비즈니스 모델(수익 구조) 설계, 사업계획서 작성 및 리뷰, 투자 유치 준비 및 전략

**경영 자문**: 법인 설립(종류, 절차), 세금 신고(이해, 신고 방법), 재무제표(이해 및 분석), 경영 전략(성장 전략 수립)

## 6. 가격 정책


### 6-1. 빌더 계정 개설비

**300만원 (얼리버드, 부가세 포함)**, 최초 1회 납부입니다.

**포함 내역:** 플랫폼 모든 기능 이용권, AI 크레딧 5만원, Sunny 1:1 코칭 3개월, Books/Tips/가이드 전체 접근, Dev Package 다운로드 권한, 예시 프로젝트 소스코드 접근 권한

**50% 환불 인센티브:** 3개월 내에 다음 조건을 모두 달성하면 150만원을 환불합니다 - 풀스택 웹사이트 완성 + 실제 서비스 런칭 + 유료서비스 이용자 30명 이상 확보(증빙 제출)

**가치 상승 예고:** 현재 300만원에서 향후 3,000만원까지 인상 예정. 예시 프로젝트 100개가 제공되면 1주일 안에 풀스택 웹사이트를 만들 수 있게 됩니다.

**빌더 계정 양도:** 타인에게 시가로 양도하는 것을 공식 인정합니다.


### 6-2. 월 이용료

월 5만원 (부가세 포함)이며, 처음 3개월은 무료입니다. 4개월차부터 과금이 시작됩니다.


### 6-3. AI 크레딧

#### 기본 제공

빌더 계정 개설 시 5만원이 초기 제공됩니다.

#### 추가 충전

부족하면 충전해야 합니다.


### 6-4. 수익 활용

빌더 계정 개설비 수입의 50%는 창업자들에게 투자하는 재원으로 사용되고, 50%는 운영비로 사용됩니다.


## 7. 향후 계획


### 7-1. 예시 프로젝트 확대

현재 1개(SSAL Works)에서 시작하여 조만간 3개, 내년 50개, 장기적으로 100개까지 확대할 계획입니다.

## 8. 용어 정리


**주요 용어**

- **SSAL Works**: Claude Code 활용 3차원 SAL Grid 기반 풀스택 웹사이트 개발 플랫폼
- **SAL Grid**: Stage, Area, Level 3차원 좌표계 프로젝트 관리 방법론
- **회원**: SSAL Works에 무료 가입한 사용자
- **빌더 계정 개설자**: 개설비를 납부하고 빌더 계정을 활성화한 사용자
- **PO (Project Owner)**: 빌더 계정을 개설하여 프로젝트를 진행하는 사람. 빌더 계정 개설자와 동일
- **프로젝트**: 빌더가 등록한 웹사이트 개발 프로젝트
- **개발**: AI와 협업하여 웹사이트를 만드는 과정
- **Task**: SAL Grid의 개별 작업 단위
- **Order Sheet**: AI에게 작업을 지시하는 표준화된 양식
- **Briefing**: 각 단계별 안내문
- **Dev Package**: AI 협업 웹 개발 올인원 패키지
- **Stage Gate**: 각 Stage 완료 시 수행하는 품질 검증 시스템
- **Sunny**: SSAL Works 개발자 겸 창업자
